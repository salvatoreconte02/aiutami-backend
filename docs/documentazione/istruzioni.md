AUI Project Documentation - General structure
1. Cover
(project title, list of group members with name/surname/email) + abstract (max 150 words)
2. The team
(list of group members with PICTURE/name/surname)
3. Members’ Contribution
(a table in which each line associates a group member to a paragraph describing the task(s) in
which she or he was involved as RESPONSIBLE or CONTRIBUTOR)
4. Table of contents
(with page numeration)
5. Executive Summary
(max 1 page summarizing the main problem (requirements) and the proposed solution (in terms
of UX and technology) along with the "value proposition")
6. Requirements
The problem that you want to address; Please refer to the UNG model and include the UNG
diagram
- Main Target Groups/STAKEHOLDERS
- NEEDS OF THE STAKEHOLDERS that your project wants to address
- CONTEXT where such needs emerge (and where your solution will be used)
- CONSTRAINTS, if any
- GOALS: what your system wants to achieve
- NEEDS = properties of stakeholders/end users.
1
- GOALS = properties of your technological system.
7. State of the art
(related works/projects/products)
8. Solution - UX Design
- General approach: max 1 page narrative.
- Description depends on project type.
- User workflow(s): diagram(s) of the flow of the main users’ tasks.
- User Scenarios: including textual descriptions, screenshots or other images.
- Conversational interaction - if applicable: describe the general characteristics of
the user(s)-system dialogue, the role played by the conversational agent(s), the approach
adopted to control their behavior. Report key examples of prompts in this section and
include additional examples (if relevant) in a dedicated Appendix
9. Solution - Implementation
- HW architecture (if applicable)
- SW architecture (functional + implementation)
10. Empirical Evaluation (if performed)
Describe the evaluation goal and the variables you wanted to measure, the profile (and number)
of the users involved, the tasks they performed, the data gathering method, and the main results
of the evaluation
11. Value proposition / Onliness statement
- Value for users and uniqueness.
- Why it is a good solution.
- Competitors and comparison.
12. Discussion and Future work
- Critical reflection.
- Future developments.
13. Optional: Business perspectives
14. Bibliography
ACM or IEEE format required.
15. Annexes (optional)
Any additional material that can be helpful to complete the description of your prototype, e.g.:
- Screenshots or images helpful to prepare a user manual
- Details about the prompts used for the conversational agents
- Implementation details
- ...
